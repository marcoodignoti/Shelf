# OpenNotion v0.2.0

OpenNotion `v0.2.0` hardens the page export/import feature introduced in
`v0.1.9` and adds an automatic database safety net for app updates.

## Changes

- Export and import now run their file access entirely in the trusted main
  process: the interface layer can no longer ask the system to read or write
  arbitrary files. Exports are also size-capped and validated against path
  traversal.
- Exporting a page tree or project notes works correctly on Windows paths,
  follows the file name picked in the save dialog, and pages with the same
  title no longer overwrite each other's exported files (they get numeric
  suffixes).
- On the first launch after an app update, the database is snapshotted into
  a `backups/` folder before any schema migration runs, keeping the five
  most recent backups. A bad migration can no longer touch the only copy of
  your data.
- Studio PDF performance now has a measured baseline and a profiling test
  (`docs/perf/studio-pdf-profile.md`): opening a document takes the same
  time at 10 or 800 pages, and memory stays flat thanks to off-screen page
  bitmap release.

## Tester Notes

Existing notes, Studio documents, and settings are untouched. The first
launch of `v0.2.0` writes a one-time database backup to
`backups/opennotion-v0.1.x-<timestamp>.db` inside the app data folder —
that is expected and is your rollback copy.
